# Triage brief — 2306.02873 — DecompX: Explaining Transformers Decisions by Propagating Token Decomposition

Source: https://arxiv.org/abs/2306.02873
Triaged: 2026-04-29

## Refutations

1. **F-2 (Prefill L19 DoM AUROC 0.7731 framed as a "single direction" correctness predictor) could be reduced to a sparse-token attribution artefact.**
   *Mechanism*: DecompX shows a transformer's hidden state at layer ℓ is the linear sum of decomposed contributions from each input token (Eq. 1: x^ℓ_i = Σ_k x^ℓ_{i⇐k}). If we apply the same decomposition to Qwen-2.5-1.5B prefill activations at L19 and project each per-input-token contribution onto our DoM direction, the AUROC 0.7731 signal might be carried by a small subset of tokens (e.g. the question's numerical operands or the trailing instruction phrase) — i.e. it would be a *token-attribution* phenomenon dressed up as a *geometric direction*. The 0.046 cos(prefill_DoM, final_DoM) (orthogonality, F-3) would still hold but for a less interesting reason: prefill DoM is "this question is hard" lexicon, not a global representational axis.
   *Falsifier*: decompose the L19 prefill activation per-input-token, project onto DoM, measure attribution concentration (entropy / Gini). If the top-5% of input tokens carry ≥70% of |DoM-projection|, F-2 is reframed.

2. **F-7 (D-bucket distinctive collective geometric signature) would be undermined if D-bucket problems share a *token-level* attribution profile rather than a collective geometric one.**
   *Mechanism*: F-7's "collective" framing assumes the signature lives in geometry, not in lexical content. DecompX's per-token decomposition would let us check whether D-bucket prompts disproportionately attribute prefill activation mass to a particular token *type* (e.g. equation tokens, single number patterns, problem-statement boundary). If yes, D-bucket's fragility (K=1 right, K=8 wrong, F-7 §1b) is not a geometric phenomenon but a "single-token-dominance triggers a single brittle reasoning pathway" phenomenon — the same fragility reported in Akli et al. 2604.24712 for under-specified code prompts (already wired to H-21).
   *Falsifier*: compute per-input-token attribution entropy at L19 prefill across the 36 D-bucket and 207 A-bucket problems. If D-bucket entropy is significantly lower (say > 1 SD), F-7's "geometric signature" claim collapses to a token-attribution claim and overlaps H-21.

3. **H-13 (head-level attribution of prefill vs final-token circuits) is targeting the wrong granularity if FFN dominates faithfulness.**
   *Mechanism*: DecompX's leave-one-out ablation (Figure 4) shows that *removing FFN from the decomposition* drops AOPC dramatically — more than removing biases or even more than ablating the classification head on some datasets. This says, in encoder-classification land, the FFN sub-block carries most of the per-token attribution signal. If the same holds for our decoder-prefill setting, then attributing the L19 DoM signal to attention heads (the H-13 plan) will explain a small fraction; the right intervention is FFN-block-level (Geva et al. key-value-memory style).
   *Falsifier*: when implementing H-13, also include an FFN ablation arm (zero out FFN_19 contribution to the residual, recompute prefill DoM AUROC). If FFN ablation drops AUROC > attention-head ablation, H-13 should be reframed.

## Direct connections to F-N / H-N

- **F-2 (prefill L19 DoM AUROC 0.7731)** — DecompX provides the most faithful known recipe for decomposing a transformer hidden state at layer ℓ into per-input-token contributions, including FFN and biases. This is a tool we'd want to apply *to* the L19 prefill activation to ask "which prompt tokens actually carry the DoM signal?" Currently F-2 is a global linear probe with no per-token attribution; DecompX would give us one.
- **F-3 (cos(prefill, final) = 0.046)** — DecompX would also let us decompose the *final-token* activation, allowing per-token attribution comparison: prefill vs final may be orthogonal at the *direction* level but share or diverge at the *input-token attribution* level, which is a finer-grained version of the orthogonality story.
- **F-7 (D-bucket collective geometry)** — token-level decomposition is a natural diagnostic for whether D-bucket fragility is geometric (current framing) or token-dominance-based (would converge with H-21).
- **H-13 (head-level attribution)** — DecompX supersedes head-level attention attribution for faithfulness; should be folded in.

## Methodologies extracted

- **Layer-wise decomposition propagation (no rollout)** — track each input token's contribution vector x^ℓ_{i⇐k} through every encoder block instead of collapsing to scalar attributions then aggregating with rollout. Eliminates the information-loss step that ALTI/GlobEnc/attention-rollout pay.
  *Replication cost*: 1–2 weeks of careful porting from BERT-encoder to Qwen decoder-only (no CLS, replace classification head with unembedding or DoM projection); reference impl at github.com/mohsenfayyaz/DecompX.
  *We'd plausibly run this*: yes — would refine F-2 and F-7 via per-input-token attribution at L19. High variance in cost — could also do a much cheaper grad-×-input approximation first.
- **FFN decomposition via point-wise activation linearization** — for each output coordinate t, define θ_t = f_act(x^t)/x^t and treat the FFN as a linear map (input-dependent diagonal scaling). Crucial for keeping the decomposition exact through GeLU/SiLU.
  *Replication cost*: trivial once you have the decomposition framework — adds one elementwise division per FFN.
  *We'd plausibly run this*: yes — required to extend any decomposition to Qwen's SwiGLU FFNs.
- **AbsDot bias decomposition** — split each component's bias across the N input tokens proportional to |b · x^ℓ_{i⇐k,NoBias}|. Gives a principled way to attribute biases without overweighting padding-like low-norm tokens.
  *Replication cost*: trivial.
  *We'd plausibly run this*: yes — biases in Qwen FFNs/attention are non-trivial; cannot be ignored if we want sums to recover the true activation.
- **Classification-head propagation for per-class attribution** — propagate decomposed CLS-token vectors through the classifier so each input token gets a per-class logit contribution. Yields signed attributions (token X pushed prediction +5 on Positive, −3 on Negative).
  *Replication cost*: low *if* we replace the classification head with our DoM projection (a 1-d linear functional). Becomes "per-input-token contribution to DoM-projection" — directly addresses the F-2 refutation.
  *We'd plausibly run this*: yes — this is the smallest useful import from DecompX for our pipeline.
- **AOPC / Accuracy / Predictive-Performance faithfulness evaluation** — perturb the K% most/least important tokens by [MASK], measure AOPC (probability change), Accuracy (class flip rate), and rationale-only Pred Perf. Standard but worth importing for any future attribution work.
  *Replication cost*: medium — needs a "[MASK]"-equivalent for decoder generation (e.g. token replacement with the model's prior, or removal). Probably 1 day to adapt.
  *We'd plausibly run this*: maybe — only if we publish a token-attribution claim that needs a faithfulness sanity check.

## Approaches & framings

- **"Faithful = no information loss in aggregation"** — DecompX argues rollout (scalar aggregation then re-multiplication across layers) destroys the multi-dimensional impact of each token. By propagating *vectors*, you preserve everything. This reframes how we should think about *any* per-layer decomposition of our L19 activations: don't summarise via norms, propagate the decomposed components.
- **"Per-class attribution beats absolute importance"** — DecompX gives signed contributions per output class, not an absolute saliency. Mapping into our setting: we could extract per-input-token signed contributions to *DoM-projection* (a scalar with sign) rather than asking for absolute "importance" — the sign would directly tell us which tokens push toward "predicted correct" vs "predicted incorrect".
- **"Faithfulness over plausibility"** — DecompX explicitly chooses faithfulness metrics (AOPC, Accuracy) over human-plausibility (highlight-style ratings). We've largely been operating in the same regime (probe AUROC, OOF), but the paper makes the case crisp.

## Implementation details worth capturing

- Code: github.com/mohsenfayyaz/DecompX (PyTorch, BERT/RoBERTa via HF Transformers).
- Models: BERT-base-uncased and RoBERTa-base, fine-tuned per task. Single RTX A6000 24GB suffices.
- Activation linearization: f_act(x) ≈ θ ⊙ x with θ_t = f_act(x^t)/x^t. Approximate but the sum-of-decomposed-vectors recovers the original activation exactly.
- LayerNorm decomposition: lifted from Kobayashi 2021 — re-expressed as a linear function g_{x⁺}(z_{i⇐k}) per token plus a single bias vector γ. Includes the LN bias β (which Kobayashi/Modarressi previously dropped).
- AbsDot weights: ω_k = |b · z^ℓ_{i⇐k,NoBias}| / Σ_k|b · z^ℓ_{i⇐k,NoBias}|. Splits each bias across inputs by alignment with the token's no-bias contribution.
- Faithfulness eval: 0%, 10%, 20%, …, 90% perturbation rates; replace tokens with [MASK] (not delete) to keep input on-distribution.
- Integrated Gradients baseline: step size 0.1, L2-norm of gradient as scalar attribution.

## Replicable intermediates

- **Smallest possible cross-check on cached prefill activations**: use a *gradient × input* approximation of token attribution on the L19 prefill activation projected onto DoM. We have cached `pathway11_h100/prefill_gated_compute/` activations + the fitted DoM probe. Compute ∂(prefill_activation · DoM)/∂(input_embedding) ⊙ input_embedding for each problem, summed per input token. Then compute attribution-entropy per problem and compare D-bucket vs A-bucket distributions. This is *not* DecompX (less faithful) but is the cheapest probe of the F-2 / F-7 refutation hypotheses, ~30 min on cached NPZs. If the entropy distributions overlap substantially, the refutations don't fire and we don't need full DecompX.
- The DecompX headline (AOPC on SST-2 = 0.627 vs ALTI 0.416) is an encoder-classification claim and not directly replicable in our pipeline.

## Proposed PAPER_INDEX.md classification

## 2306.02873 — DecompX: Explaining Transformers Decisions by Propagating Token Decomposition (Modarressi et al., ACL 2023)

**Relevance:** DecompX is the most faithful known recipe for decomposing a transformer hidden state at layer ℓ into a sum of per-input-token contributions by propagating decomposed *vectors* through every component (attention, FFN with linearised activation, biases via AbsDot, classification head) without rollout. Although the paper targets encoder-only BERT/RoBERTa on classification, the decomposition principle ports directly to our decoder-only Qwen-2.5 setting. It supplies a principled way to ask "which input tokens carry our prefill L19 DoM signal (F-2)?" — a per-token attribution that we currently lack and that would either refine or refute the "single direction" framing.

**Key claim we tested:** Transformer hidden states are exactly the linear sum of per-input-token contribution vectors when FFN/biases/LayerNorm are properly decomposed; faithful per-token attribution requires propagating these vectors instead of aggregating with rollout.

**Our result:** **TO TEST** — The methodology is sound but only the cheap gradient×input variant (P11-FE73) is runnable on cached data; full DecompX-style propagation needs a 1–2 week port to Qwen (P11-FE74). If FE73's per-problem attribution-entropy distribution is sufficiently narrow on the high-correctness side, F-2's "geometric direction" framing is reframed as a sparse-token-attribution phenomenon — see H-73.

**Related experiments:** P11-FE73, P11-FE74, P11-FE75, H-73, H-74, H-13, H-21.

**Status:** TO TEST (H-73, HIGH priority).
