# Triage brief — 2310.03716 — A Long Way to Go: Investigating Length Correlations in RLHF

Source: https://arxiv.org/abs/2310.03716
Triaged: 2026-04-29

Singhal, Goyal, Xu, Durrett — COLM 2024. Llama-7B + LoRA on WebGPT / Stack /
RLCD. Demonstrates length-only reward reproduces ~most PPO win-rate gains
(56% vs 58% on WebGPT, 64% vs 63% on RLCD against SFT). Non-length reward
gain (NRG) is only 2% of overall ∆R on WebGPT. Reward-model length
correlations: 0.55–0.72 Pearson across batches. Reward models confidently
predict the wrong answer on the long-output side; preference-data cartography
shows most pairs are near-zero confidence.

This is an RLHF/preference-modeling paper, not a hidden-state / reasoning
paper. Its relevance to topo-confidence is methodological: the paper's NRG
length-stratification recipe is a refutation pattern that directly applies
to any AUROC headline number we report on MATH-500 1024-tok labels.

## Refutations

1. **F-2 (Prefill L19 DoM AUROC = 0.7731 OOF on Qwen-2.5-1.5B) may be a
   length-confound.**
   *Mechanism:* the paper shows complex evaluations can be reproduced by simple
   length-correlated features. MATH-500 problem prompts vary substantially in
   token length, and easier problems may have systematically shorter or longer
   prompts. The prefill DoM is computed at the final prefill token of L19, so
   anything correlated with prompt-length-class would be encoded in the
   geometry the probe picks up. The 0.7731 OOF AUROC could be partly
   "shallow-feature explainable" rather than a deep correctness signal.
   *Falsifiable test:* compute AUROC of `prompt_token_count` alone as a
   correctness predictor on MATH-500 K=1 (Qwen-2.5-1.5B). If a univariate
   length predictor reaches AUROC ≥ 0.65, the F-2 signal is at least partly a
   length artifact. Then run NRG-style decomposition: length-stratify into
   ~5 buckets, compute prefill-DoM AUROC within each bucket, weight by bucket
   size. If within-bucket weighted AUROC < 0.7, the F-2 headline overstates
   the geometric content of the signal.

2. **F-8 (selective-prediction 71.6% acc at coverage 0.5, K=2.5 avg) may
   exploit a length-difficulty correlation rather than picking out
   geometrically-confident cases.**
   *Mechanism:* selective prediction using prefill-DoM is exactly the kind of
   "complex evaluation looking deep but driven by a simple feature" pattern
   the paper's Table 2 illustrates (LPPO ≈ standard PPO on win-rate). The
   paper's lesson generalizes: if length predicts difficulty, the
   selective-prediction frontier is partially a length frontier. The
   coverage=0.5 number gives a shallow predictor a lot of room to look
   deep.
   *Falsifiable test:* implement the selective-prediction frontier using
   `-prompt_token_count` (i.e. "answer the shorter problems first") as the
   gate. Compare acc@coverage 0.5 vs F-8's 71.6%. If length-only gating is
   ≥ 65%, F-8's "geometric selective prediction" framing is partially
   refuted. Also: re-run F-8 inside length-balanced subsets (paper's BAL
   intervention applied to MATH-500), report acc@coverage 0.5 within each
   length band.

3. **F-9 (CoE-60 trajectory features redundant with single-layer L19 DoM)
   generalizes one level further: single-layer L19 DoM is itself
   redundant with shallow lexical features.**
   *Mechanism:* F-9 already documents a complex-feature-collapsing-to-simple
   pattern. The paper extends the pattern: any ostensibly-complex
   geometric predictor in this regime should be checked against shallow
   lexical-statistical predictors, not just against other geometric
   predictors. CoE-60 → single-layer DoM → ??? — the chain may not stop
   at L19.
   *Falsifiable test:* train logistic regression on 5–10 shallow features
   (prompt token count, # of numerals in prompt, # of LaTeX `\\` macros,
   mean token length, presence of "prove"/"find"/"compute" keyword,
   subject-tag if available) for K=1 correctness. If LR AUROC ≥ 0.70 on
   MATH-500, the L19 DoM signal is mostly recoverable from shallow features
   and the "geometric correctness signal" framing for F-2/F-9 needs heavy
   qualification.

4. **F-4 / F-7 (asymmetric collapse and D-bucket geometric signature) may
   share a length-tail confound.**
   *Mechanism:* D-bucket is K=1 right, K=8 wrong — a tail effect over 8
   samples. Output-length variance is highest in the tails, and the
   asymmetric-collapse signature (correct collapses harder than incorrect
   at final token) is computed at final token across heterogeneous
   trajectory lengths. The paper's recurring finding is that long-tail
   subsets carry length signatures that propagate as if they were content
   signatures. H-15 already encodes this concern for F-4; the present
   paper extends the same recipe to F-7.
   *Falsifiable test:* length-stratify the D-bucket detection — compute
   the D-bucket geometric signature inside each of 4 length bands, ask
   whether the per-band AUROC for D-bucket membership survives. Pair
   with H-15's length-band PR control for F-4 (P11-FE15, already
   READY).

## Methodologies extracted

- **NRG (Non-length Reward Gain) decomposition** — split a metric into
  within-bucket gain (length-bucketed, weighted by bin size) and
  across-bucket gain. Direct port: split prefill-DoM AUROC into
  within-length-bucket discrimination + across-length-bucket
  discrimination contributions.
  *Replication cost:* 30 min CPU on cached `pathway11_h100/prefill_gated_compute/` NPZs.
  *We'd plausibly run this:* yes — it's a direct NRG-for-AUROC adaptation.
- **Length-only adversarial reward (LPPO)** — define a metric using only
  the suspected confound, see how much of the headline it reproduces.
  Port: train a univariate logistic regression on `prompt_token_count`
  for K=1 correctness, report AUROC against the 0.7731 baseline.
  *Replication cost:* 20 min CPU.
  *We'd plausibly run this:* yes — adversarial baseline for F-2.
- **Length heuristic agreement** — accuracy of always-pick-the-longer-output.
  Port to our regime: accuracy of "always-correct-on-the-shorter-prompt"
  as a baseline.
  *Replication cost:* 5 min CPU.
  *We'd plausibly run this:* yes, as part of FE83 below.
- **Length-balancing of preference data (BAL)** — subsample so paired
  length-differences are symmetric in 10-token bins. Port: length-balance
  MATH-500 problems (subsample to flatten the length distribution),
  recompute F-2 / F-8.
  *Replication cost:* 30 min CPU + reduces effective N (probably 250–350
  problems out of 500).
  *We'd plausibly run this:* yes.
- **Confidence-based truncation (C-TR)** — use data cartography to
  identify low-confidence training examples, train only on those.
  Port: identify low-DoM-confidence MATH-500 problems, see whether
  AUROC is recoverable on the low-confidence subset alone.
  *Replication cost:* 30 min CPU.
  *We'd plausibly run this:* probably no — low-priority diagnostic.
- **Reward Data Augmentation (R-DA)** — random pairing of prompts
  to break feature reliance. Doesn't have a clean port to our setting
  (we're not training a reward model).
  *Replication cost:* n/a.
  *We'd plausibly run this:* no — no analogous training stage.
- **Training-dynamics confidence cartography (Swayamdipta et al.)** —
  track per-example confidence across epochs to find easy/hard
  examples. We don't train probes for many epochs, but the
  cross-fold (5-fold OOF) confidence variance is a cheap analogue.
  *Replication cost:* 20 min CPU.
  *We'd plausibly run this:* maybe — only if FE83/FE84 above show
  length confounds, then this is the next diagnostic.

## Approaches & framings

- **"Shallow-feature dominance over complex-feature evaluation"** —
  the paper's central frame. Maps directly onto F-2 / F-8 / F-9 as a
  refutation pattern. Implication for the project: every probe-style
  AUROC headline should be paired with a shallow-feature LR baseline
  before it goes into FINDINGS.md.
- **"NRG ratio as the discriminating metric"** — instead of asking "is
  the metric good?", ask "what fraction of the metric is attributable
  to the simple feature alone?" This frames the validate_claims.py
  91-claim invariant differently: the invariant guards numerical
  reproducibility, not feature-attribution validity. NRG-style
  audits would be a separate axis of validation.
- **"Reward models as the locus of bias"** — the paper localizes the
  length bias to reward modeling, not PPO optimization. Translated to
  our setting: bias would localize to the labeling pipeline (K=1
  correctness, PROOF-format dependent), not to the geometric extraction.

## Implementation details worth capturing

- Llama-7B base, LoRA rank 16, TRL implementation, λ=0.04 baseline KL
  coefficient.
- LPPO target lengths: 156 (WebGPT), 120 (RLCD), 250 (Stack) — set as
  hyperparameter to "allow desired increases without becoming too long".
- Length penalty `R' = R + (1 − len(y)/N) σ` where σ is moving-average
  batch reward standard deviation.
- 20-token bucket size for length stratification (Figure 3, Table 1)
  — small enough that buckets contain meaningful data, large enough to
  smooth noise. For MATH-500 prompts (typically 50–500 tokens), 50-token
  buckets seem more appropriate.
- Reward model "confidence" computed per training example as `R(x, y+) −
  R(x, y−)` averaged over epochs 2..E (epoch 1 excluded for noise).
- Convergence note: stricter length penalties cause training divergence
  — calibration is delicate.
