# Triage brief — 2312.04762 — The Graph Lottery Ticket Hypothesis: Finding Sparse, Informative Graph Structure

Source: https://arxiv.org/abs/2312.04762
Triaged: 2026-05-06

## Refutations

**R1 — Against F-10 (PH null): over-dense neighborhood graphs may mask topology that becomes visible at the right sparsity level.**
F-10 found that PH summary statistics on residual streams are indistinguishable from a Gaussian null. But PH was computed on dense Vietoris-Rips complexes — effectively the complete weighted graph on activation vectors. Tsitsulin & Perozzi show that graph learning performance is preserved (often improved) on extremely sparse backbones (avg degree ~5). If we built an epsilon-ball or k-NN graph from L19 prefill activations and applied kTree sparsification *before* computing PH, the "lottery ticket" subgraph might expose topological features invisible in the dense regime — the dense complex may be over-smoothing persistent homology, exactly as dense graphs over-smooth GNN gradients. A non-null PH result on the sparse backbone would refute F-10's mechanism claim ("training erases topology") by showing topology was present but hidden by density.
*Falsifiable test:* Build k-NN graph (k=10,20,50) from cached 500×1536 L19 prefill activations, apply kTree to target avg degree 5, compute H_0/H_1 barcodes on the sparse subgraph's clique complex, compare correct vs incorrect vs Gaussian null.

**R2 — Against F-2 (DoM as single direction, AUROC 0.7731): graph-structural features of activation neighborhoods could outperform the directional probe.**
F-2 frames correctness prediction as a directional signal (projection onto a single vector in R^1536). But the GLT results show that *connectivity structure* — spectral properties like algebraic connectivity, effective resistance — carries more discriminative information than local metrics like clustering coefficient. If we built a k-NN graph from L19 activations and used graph-structural features (spectral gap, effective resistance of each node's neighborhood, Forman curvature) as correctness predictors, achieving AUROC > 0.7731 would refute the "single direction suffices" conclusion by showing the signal is relational/topological rather than directional.
*Falsifiable test:* Build k-NN graph from cached activations, compute per-node effective resistance and node-level spectral features, train logistic regression for correct/incorrect, compare AUROC to 0.7731.

**R3 — Against F-9 (CoE-60 redundant with single-layer DoM): multi-scale graph structure across layers might carry non-redundant information.**
F-9 found CoE-60 trajectory features are redundant with single-layer L19 DoM. The GLT result that unions of *multiple* random spanning trees (kTree) systematically outperform single trees (1Tree) — especially for embedding tasks — suggests that multi-scale structural information is genuinely complementary. If we built per-layer k-NN graphs at layers L15, L19, L23 and took the kTree union across layers, the resulting multi-layer graph features might break the DoM = CoE-60 redundancy by capturing cross-layer connectivity patterns invisible to single-layer DoM.
*Falsifiable test:* Build k-NN graphs at 3-4 layers, compute kTree union, extract graph-structural features (spectral gap, effective resistance), test AUROC vs. single-layer DoM 0.7731 and vs. CoE-60.

## Direct connections to F-N / H-N

- **F-2 (Prefill L19 DoM AUROC 0.7731):** The paper's finding that avg degree ~5 preserves graph learning performance implies that if the correctness signal has a graph-neighborhood interpretation, only ~5 nearest neighbors per problem in activation space might be needed. The 500-sample MATH-500 dataset at avg degree 5 would yield only ~2500 edges total — a tractable structure for graph-based correctness classification as a DoM alternative.

- **F-10 (PH null):** Graph sparsification directly intersects the PH computation pipeline. Tsitsulin et al.'s spectral sparsification (preserving Laplacian quadratic forms to (1±ε) factor) provides a principled way to thin the simplicial complex input to PH while preserving its spectral properties. This is a concrete mechanism by which F-10's null result could be an artifact of the dense regime rather than a genuine absence of topology.

- **F-7 (D-bucket collective signature):** The paper's curvature framework (Forman, Ollivier, effective resistance) offers alternative metrics for characterizing the "collective geometric signature" of the D-bucket. If D-bucket activations occupy a region of activation space with distinctive graph curvature (e.g., more negative Forman curvature → tree-like structure vs. clique-like for correct answers), this would give the collective signature a graph-theoretic characterization.

- **H-4 (Breathing ↔ Sharpness Dimension):** The paper's spectral dimensionality concept (eigenvalue growth rate of graph Laplacian) is a graph-level analogue of the covariance spectrum analysis underlying the cov-spectrum probe (AUROC 0.7928). Computing the Laplacian spectral dimension of activation k-NN graphs could bridge graph-structural and linear-algebraic framings of the breathing phenomenon.

## Methodologies extracted

- **kTree (union of k random spanning trees)** — Iteratively union random spanning trees of an input graph until reaching a target edge budget. Preserves connectivity and approximates spectral properties.
  *Replication cost*: 10min CPU (our graphs would be 500-node, trivial).
  *We'd plausibly run this*: yes — as a preprocessing step before graph-based analyses of cached activations.

- **Spectral sparsification via effective resistance weighting** — Weight edges by effective resistance (probability of inclusion in random spanning tree), then sample. Preserves Laplacian quadratic forms.
  *Replication cost*: 10min CPU for 500-node graph.
  *We'd plausibly run this*: yes — as a principled graph thinning step.

- **Graph robustness metrics suite (8 metrics)** — Algebraic connectivity (λ₂), spectral radius, effective resistance, number of spanning trees, number of triangles, global/local clustering coefficient, Forman curvature. Computed via stochastic Lanczos quadrature for eigenvalue-dependent metrics.
  *Replication cost*: 15min CPU for the full suite on a 500-node graph.
  *We'd plausibly run this*: yes — these could serve as alternative features for correctness prediction from activation-space neighborhood graphs.

- **Forman/Ollivier curvature on graphs** — Edge-level curvature measures quantifying local geometry (clique-like vs. tree-like neighborhoods). Forman curvature is O(m) to compute.
  *Replication cost*: 5min CPU.
  *We'd plausibly run this*: yes — as node-level features aggregated from edge curvatures on activation k-NN graphs.

## Approaches & framings

- **Lottery ticket as structural redundancy:** The core insight that most graph structure is redundant for downstream tasks could reframe F-10: PH may be null not because topology is absent, but because dense VR complexes encode massively redundant structure that washes out group-discriminative signal. Sparsify first, then compute topology.

- **Spectral vs. local metrics hierarchy:** The paper establishes that spectral properties (algebraic connectivity, effective resistance) are more informative than local properties (clustering coefficient, triangles) for graph quality. This parallels our finding that covariance-spectrum features (spectral, AUROC 0.7928) outperform single-direction DoM (0.7731) — both cases favor global spectral structure over local features.

## Implementation details worth capturing

- kTree algorithm is near-linear O(m^{1+o(1)}) in edges via the Schild 2018 random spanning tree algorithm.
- For eigenvalue-dependent metrics, they use stochastic Lanczos quadrature (Ubaru et al. 2017) with 100 starting vectors and 10 iterations — good defaults for our 500-node scale.
- Graph connectivity must be preserved as a hard constraint (most graph learning algorithms fail on disconnected graphs); kTree guarantees this by construction (spanning tree is connected).
- No code link provided in the paper, but kTree/1Tree are trivial to implement (~20 lines with NetworkX).
