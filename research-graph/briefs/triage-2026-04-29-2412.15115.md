# Triage brief — 2412.15115 — Qwen2.5 Technical Report

Source: https://arxiv.org/abs/2412.15115
Triaged: 2026-04-29

This is the official Qwen2.5 model card / technical report. Qwen-2.5-1.5B is
the project's primary residual-stream donor — every F-1..F-10 finding in
`~/topo-confidence/FINDINGS.md` is computed on activations from the released
Qwen2.5-1.5B-Instruct checkpoint. The paper is therefore a *Reference paper*:
it is unlikely to overturn our findings on its own, but it documents the
architectural and training-data choices that *generated* the activations we
probe. The refutations below are mechanistic confounds the paper surfaces —
each one is a design decision in Qwen2.5-1.5B that, if load-bearing for one
of our findings, would force us to scope or revise the claim.

## Refutations

1. **Tied input/output embeddings on Qwen2.5-1.5B confound F-3's "prefill ⊥
   final-token" claim.** Table 1 of the paper documents that Qwen2.5-0.5B,
   1.5B, and 3B use *tied embeddings* (`Tie Embedding: Yes`), while 7B, 14B,
   32B, and 72B do *not* (`No`). F-3 reports cos(prefill_DoM, final_DoM) =
   0.046 on the 1.5B and treats this as evidence of two functionally distinct
   circuits. But with tied embeddings the unembedding row space is *literally
   the same matrix* as the input embedding space, so a "prefill direction"
   probing-content tokens and a "final-token direction" probing answer-tokens
   have an extra structural reason to be near-orthogonal: they pick out
   disjoint vocabulary subsets that are projected through the same shared
   matrix. **Mechanism:** the 0.046 cosine could be a vocabulary-space
   artifact rather than a circuit-level claim.
   **Falsifiable experiment:** measure cos(prefill_DoM, final_DoM) on
   Qwen2.5-7B (untied) using P11 H100's existing 7B residual cache. F-3
   predicts ≤0.10; if 7B comes back ≥0.30, the orthogonality is partly an
   artifact of tied embeddings on 1.5B and F-3 needs scoping to the
   tied-embedding subseries.

2. **GQA with 12 Q / 2 KV heads on 1.5B fundamentally limits H-13's
   head-level circuit attribution.** Table 1 shows Qwen2.5-1.5B has only 2 KV
   heads (vs 12 query heads). All 12 query heads share KV state through one
   of two pools, so attention information is heavily *redundant across query
   heads* — head ablation studies cannot isolate a "prefill head" from a
   "final-token head" in the way a true MHA model would allow. **Mechanism:**
   H-13 ("head-level attribution of prefill vs final-token circuits") may be
   *empirically untestable on 1.5B* — any apparent head specialization is
   conditioned on the same 2 KV pools and does not constitute independent
   circuits. **Falsifiable experiment:** run head-attribution probes on
   Qwen2.5-7B (4 KV heads) and Qwen2.5-14B (8 KV heads) using the same
   protocol; if the attribution structure changes qualitatively with KV-head
   count, H-13 needs to be re-stated as a property of GQA-grouping rather
   than of attention heads.

3. **Pre-training was filtered by Qwen2-Math-RM-72B — F-2's "DoM predicts
   correctness" may be circular.** §3.1(3) reports that Qwen2.5 synthetic
   training data was filtered using "our proprietary general reward model and
   the specialized Qwen2-Math-RM-72B" *during pre-training*, and §4.1(2)
   adds Qwen2.5-Math chain-of-thought data filtered by reward modeling. F-2
   claims AUROC 0.7731 for the L19 prefill DoM as a generic *correctness*
   predictor. But because the training distribution itself was shaped to be
   "Qwen2-Math-RM-72B-correct", any direction recovered by a label-supervised
   probe could be the *Qwen2-Math-RM-72B-likeness direction* rather than a
   generic "the model knows it's right" direction. **Mechanism:** label
   leakage through pre-training data filtering. **Falsifiable experiment:**
   evaluate the L19 DoM probe on a held-out task whose correctness signal is
   *uncorrelated* with Qwen2-Math-RM-72B preferences (e.g., a coding task
   scored by execution rather than by RM). If AUROC drops sharply, F-2 is
   partly a recovery of the RM filter and the "correctness" framing needs
   replacing with "RM-policy alignment".

4. **GRPO online RL with variance-prioritized query ordering inflates F-8's
   selective-prediction headline.** §4.3 documents that GRPO query order is
   "determined by the variance of their response scores, as evaluated by the
   reward model. Specifically, queries with higher variance in response
   scores are prioritized." This means the post-trained model has been
   *specifically over-trained* on queries where its own outputs are
   uncertain. F-8 reports 71.6% selective accuracy at coverage 0.5 on the
   Instruct model. **Mechanism:** the high-variance query prioritization in
   GRPO compresses the model's confidence distribution toward the
   selective-prediction sweet spot, inflating the apparent gain from L19 DoM
   gating. **Falsifiable experiment:** run the F-8 selective-prediction
   protocol on Qwen2.5-1.5B *base* (no GRPO) and compare to the Instruct
   value of 71.6%. If base shows comparable selective accuracy, F-8 reflects
   a generic property of the residual stream; if base is much weaker, F-8 is
   partly an artifact of GRPO post-training.

5. **Two-phase pre-training with RoPE base 10K → 1M (ABF) destabilizes H-8's
   "DoM is stable across training checkpoints" prediction and reinforces
   H-17's RoPE-mechanical conjecture.** §3.3 reports a two-phase pre-training
   with RoPE base frequency *re-scaled from 10,000 to 1,000,000* via the ABF
   technique during context-length expansion. Any DoM direction extracted
   from the released checkpoint reflects the post-ABF geometry; geometry on
   the 4K-context, RoPE-base-10K early checkpoint may be qualitatively
   different. **Mechanism:** if the prefill-DoM direction is partially a
   function of RoPE base frequency (H-17), then H-8 ("DoM is stable across
   checkpoints") is predicted to *fail* across the pre→post-ABF boundary.
   **Falsifiable experiment:** if Qwen ever releases an early-checkpoint
   Qwen2.5-1.5B (4K context, RoPE=10K), re-extract DoM at L19 and measure
   cos(early_DoM, released_DoM). H-8 predicts cos > 0.7; H-17 + ABF
   predicts < 0.4.

## Direct connections to F-N / H-N

- **F-1 (Dimensional breathing universal across architectures and scales)** —
  the paper documents that Qwen2.5 spans 7 dense sizes (0.5B → 72B) all
  sharing the same architecture family (RoPE + GQA + RMSNorm). This is the
  *exact substrate* on which F-1's "universal" claim is currently tested.
  The paper expands the available scale range for cross-scale breathing
  replication (currently we report 1.5B and 7B; 3B/14B/32B are open).

- **F-2 (Prefill L19 DoM AUROC = 0.7731 on Qwen-2.5-1.5B)** — the model
  config (28 layers, L19 ≈ 68% depth) is the headline anchor. The paper's
  documentation of math-data and RM filtering during pre-training surfaces
  the data-leakage refutation above (Refutation #3).

- **F-7 (D-bucket has distinctive collective signature)** — the paper
  reports that Qwen2.5-1.5B-Instruct hits MATH = 55.2 (8K-token, instruct);
  our P11 H100 reports 48.6% on MATH-500 K=1 at 1024-tok. The 6.6-point gap
  is plausibly explained by the truncation at 1024 tokens vs the paper's
  8K-token output budget — i.e., the "D-bucket" (24/500 = 4.8% of MATH-500
  in our P11 work) may be partially the population that *would* solve the
  problem at 8K tokens but is truncated at 1024.

- **H-3 (Breathing replicates on code generation)** — the paper documents
  Qwen2.5-Coder data integration during pre-training; this means
  Qwen2.5-1.5B has measurable code competency (HumanEval = 37.2 base, 61.6
  Instruct), so H-3 is testable on the same checkpoint without a model
  swap.

- **H-8 (DoM stability across checkpoints)** and **H-17 (DoM rotation is
  RoPE-mechanical)** — both are directly informed by the ABF
  RoPE-base-rescaling documented in §3.3 (Refutation #5).

- **H-13 (Head-level attribution of prefill vs final-token circuits)** —
  GQA-2-KV constraint documented in Table 1 (Refutation #2).

## Methodologies extracted

- **Adjusted Base Frequency (ABF) for RoPE rescaling** — pre-training
  RoPE base 10K → 1M (cited Xiong et al. 2023). Used to extend context
  during the two-phase pre-training.
  *Replication cost*: not relevant — we don't pre-train.
  *We'd plausibly run this*: no — but understanding it is required to
  interpret H-17 and Refutation #5.

- **YARN + Dual Chunk Attention (DCA) for inference-time length
  extrapolation** — applied at evaluation time, lets 128K-claimed models
  hold quality on RULER 64K/128K. Cited Peng et al. (YARN), An et al. (DCA).
  *Replication cost*: free — already in `transformers`.
  *We'd plausibly run this*: no for current scope (1024-tok work doesn't
  need it), yes if H-3 (code) or H-22 (Abstract-CoT) ever pushes past 8K.

- **Online Merging Optimizer (OMO) for offline DPO** — "Online merging
  optimizers for boosting rewards and mitigating tax in alignment" (Lu et
  al. 2024a). Used at LR 7e-7 for one DPO epoch over 150K pairs.
  *Replication cost*: ~$200 H100 hours for a small toy reproduction.
  *We'd plausibly run this*: no — out of scope; we don't fine-tune.

- **GRPO with variance-prioritized query ordering** — queries with higher
  RM-score variance are processed first. 8 responses sampled per query,
  global batch 2048. Cited Shao et al. 2402.03300 (DeepSeekMath).
  *Replication cost*: out of scope.
  *We'd plausibly run this*: no — but its existence underwrites Refutation
  #4.

- **Reward model evaluation across multiple benchmarks (RewardBench, RMB,
  PPE, Human-Preference-Chinese)** — §5.2.3 demonstrates that single-RM-
  benchmark optimization triggers Goodhart and *RM-benchmark scores do not
  predict downstream RL-model performance*. This is a method-level finding
  about RM evaluation, not about hidden states.
  *Replication cost*: out of scope.
  *We'd plausibly run this*: no — but the Goodhart observation is worth
  flagging as a parallel to our own concern that DoM-on-MATH-500 might not
  predict DoM on out-of-distribution tasks (Refutation #3 has the same
  shape).

- **N-gram contamination filter (LCS ≥13 tokens, ≥0.6 × min(|st|, |se|))**
  — used to detect train/test contamination during data curation.
  *Replication cost*: 30min CPU.
  *We'd plausibly run this*: no for current work, but worth knowing if we
  ever curate a held-out probe set (Refutation #3 follow-up).

- **BBPE tokenizer with 151,643 regular tokens + 22 control tokens** —
  unified across all Qwen2.5 sizes.
  *Replication cost*: free — `transformers` ships it.
  *We'd plausibly run this*: indirectly — token-budget calculations for
  P11 1024-tok labels depend on BBPE granularity.

## Approaches & framings

- **"Scaling laws for hyperparameters" rather than scaling laws for
  parameter count** (§3.2). The paper uses scaling-law fits to predict
  optimal LR and batch size as functions of (N, D), not optimal N for fixed
  compute. This reframes scaling laws from a model-design tool to a
  *hyperparameter-sweep replacement*. Intersects our work only loosely —
  but if H-10 (breathing pattern after fine-tuning) ever gets re-run, this
  would inform LR choice.

- **"Two-phase pre-training" + ABF RoPE rescaling as a single design
  pattern** (§3.3). This pattern — short-context training followed by
  long-context expansion via RoPE-base rescaling — is now the de-facto
  standard. It implies that *every released long-context model has a
  geometric discontinuity in residual-stream behavior* between phase 1 and
  phase 2 checkpoints. Directly intersects H-8 and H-17 (Refutation #5).

- **"Offline RL handles signals where standard answers exist but are
  hard for RMs" + "Online RL handles RM-judgable nuances"** (§4). This
  pipeline split (DPO-offline for math/code/reasoning, GRPO-online for
  preference/safety) is informative for any future fine-tuning experiment
  in our pathway: math/correctness signals belong in offline DPO, not
  online GRPO. Intersects H-1 (per-position DoM steering) — if we ever
  *train* a steering vector rather than probe one, this paper's pipeline
  is the correct template.

- **Goodhart's-law observation on RM-benchmark over-optimization** (§5.2.3).
  Same conceptual shape as Refutation #3 in this brief: a metric that the
  training distribution was optimized against can no longer be a clean
  evaluation metric. Worth citing in any write-up that defends F-2's
  AUROC-on-MATH-500 against label-leakage critique.

## Implementation details worth capturing

- **Qwen2.5-1.5B exact config (Table 1):** 28 layers, 12 query heads,
  2 KV heads (GQA), tied embeddings, 32K context window, 8K generation
  budget, Apache 2.0. *L19 in our work = layer 19 of 28 = ~68% depth.*
- **Activation function:** SwiGLU (Dauphin et al.). Pre-norm RMSNorm.
  QKV bias added (cited Su 2023).
- **Position encoding:** RoPE; base frequency *post-ABF* = 1,000,000.
- **SFT recipe:** 2 epochs, sequence length 32,768, LR cosine 7e-6 →
  7e-7, weight decay 0.1, gradient norm clipped at 1.0, ≈1M training
  examples.
- **DPO recipe:** 1 epoch over ~150K pairs, LR 7e-7, Online Merging
  Optimizer.
- **GRPO recipe:** global batch 2048, 8 samples per query, queries
  prioritized by RM-score variance.
- **Tokenizer:** BBPE, 151,643 regular tokens + 22 control tokens.
- **Inference-time length:** YARN + DCA enable claimed 128K context;
  Qwen2.5-Turbo additionally uses Minference (Jiang et al. 2407.02490)
  sparse attention for 1M-token context.
- **Open weights:** HuggingFace Hub, ModelScope, Kaggle. Apache 2.0 for
  0.5B/1.5B/7B/14B/32B; "Qwen Research" for 3B; "Qwen" for 72B.

## Replicable intermediates

- **Refutation #1 cross-check (untied 7B vs tied 1.5B for F-3
  orthogonality):** Cached P11 H100 1.5B and 7B prefill activations are
  in `pathway11_h100/prefill_gated_compute/`. Compute the prefill DoM and
  final-token DoM on each, then cos(prefill, final) per model. ~2h CPU.
  No new data needed. This is the cleanest single-experiment falsification
  of F-3's mechanism.

- **Refutation #2 reframing (head-attribution feasibility on
  GQA-grouping):** Run Logit-Lens-style head ablation on cached 1.5B (2 KV
  pools) and 7B (4 KV pools) prefill activations, looking at whether
  ablating one KV pool collapses the L19 DoM signal. ~4h CPU + 1h H100 if
  we re-extract pool-level activations. Tells us whether H-13 is testable
  in principle on the 1.5B.

- **Refutation #4 cross-check (base-vs-Instruct selective prediction):**
  Re-run the F-8 selective-prediction protocol on Qwen2.5-1.5B *base* using
  the existing P11 H100 pipeline; we already cache 1.5B-Instruct
  activations. New extraction on 1.5B-base = 1× H100 day, then logistic
  probe = 30min CPU.

- **F-1 cross-scale extension (1.5B and 7B already covered, 3B is the
  cheapest additional scale):** Qwen2.5-3B has 36 layers; extracting L24
  (~67% depth) prefill activations on MATH-500 would let F-1's "universal"
  claim survive an additional scale check. ~1× H100 day.

## Proposed HYPOTHESES.md additions

### H-15115: F-3's prefill/final-token orthogonality is partially a tied-embedding artifact
**Priority:** HIGH
**Motivated by:** 2412.15115 Table 1 (1.5B uses tied embeddings, 7B does not) + F-3 (cos = 0.046 on 1.5B).
**Test:** Compute cos(prefill_DoM, final_DoM) on Qwen2.5-7B using cached P11 H100 residuals. Compare to 0.046 baseline on 1.5B.
**Requires:** 2h CPU on cached prefill+final activations from `pathway11_h100/prefill_gated_compute/`. No new data.
**Would change:** Confirms F-3 mechanism if cos ≤ 0.10 on 7B; refutes the "two circuits" framing if cos ≥ 0.30 on 7B (in which case F-3 needs scoping to tied-embedding small models).
**Blocks:** any cross-scale generalization of F-3 until resolved.

### H-15116: F-8 selective prediction is partly an artifact of GRPO variance-prioritization
**Priority:** HIGH
**Motivated by:** 2412.15115 §4.3 (GRPO prioritizes high-variance queries) + F-8 (71.6% selective accuracy at coverage 0.5 on Instruct).
**Test:** Re-run F-8 selective-prediction protocol on Qwen2.5-1.5B *base*. Compare base vs Instruct.
**Requires:** 1×H100 day for base activation extraction + 30min CPU. New activation cache for base model.
**Would change:** Confirms F-8 as a generic property if base ≥ 65%; reframes F-8 as a post-training artifact if base ≤ 55%.
**Blocks:** any "selective prediction is intrinsic to residual streams" generalization.

### H-15117: L19 prefill DoM AUROC drops on execution-graded code
**Priority:** HIGH
**Motivated by:** 2412.15115 §3.1(3) (Qwen2-Math-RM-72B filtered pre-training synthetic data) + F-2 (AUROC 0.7731 on MATH-500).
**Test:** Evaluate the L19 prefill DoM probe on HumanEval/MBPP, scored by code execution rather than RM. Compare AUROC to the 0.7731 MATH-500 headline.
**Requires:** 1×H100 day for HumanEval/MBPP activation extraction + execution sandbox + 30min CPU for probe.
**Would change:** Confirms F-2 as a generic correctness direction if AUROC ≥ 0.70 on code; reframes F-2 as RM-policy-alignment if AUROC drops to ≤ 0.60.
**Blocks:** generalization of F-2 beyond math/RM-shaped distributions.
