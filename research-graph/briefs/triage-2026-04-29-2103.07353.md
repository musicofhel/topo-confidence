# Triage brief — 2103.07353 — Computing Zigzag Persistence on Graphs in Near-Linear Time

Source: https://arxiv.org/abs/2103.07353
Triaged: 2026-04-29

## Refutations

1. **F-10 (PH on trained residual streams = Gaussian null) is a *static* PH claim only.** F-10 ran Vietoris-Rips PH on point clouds at fixed (layer, token) slices — a single-snapshot filtration. Zigzag PH (this paper) handles a *time-varying* filtration with insertions **and** deletions, so it can resolve topological events (component births/deaths, 1-cycle merges) that static PH integrates out. **Mechanism of refutation**: build a 0-dim zigzag filtration where vertices = decoding tokens and edges = "hidden states within distance ε" enter/exit as the window slides; if the zigzag barcode separates correct from incorrect trajectories above the L19 DoM AUROC 0.7731 baseline, F-10's "topology is null" reading is overbroad — it should be narrowed to "static VR-PH on residual point clouds is null." **Falsifiable experiment**: construct a per-problem 0-dim zigzag filtration on cached `pathway11_h100/` L19 hidden states over decoding steps (k-NN graph with sliding window), run `fzz`, train a probe on barcode features, compare AUROC vs F-2's 0.7731.

2. **F-9 (CoE-60 redundant with single-layer L19 DoM) only tests scalar trajectory features.** CoE-60 reduces a 28-layer × T-token trajectory to 60 scalar magnitude/cosine features — that's a coarse summary. Zigzag PH on a graph filtration captures *non-scalar* trajectory structure (loops, components, holes that appear and disappear). **Mechanism**: if the trajectory has reusable cycle structure that distinguishes correct/incorrect (e.g. a 1-cycle that closes when the model reaches consistency vs stays open when it doesn't), 1-dim zigzag PH detects it directly while CoE's scalar magnitudes would average it out. **Falsifiable experiment**: extract 1-dim zigzag PH features (using the paper's O(m log⁴n) algorithm) from per-problem L19 trajectory graphs on the same MATH-500 set; if probe AUROC > 0.7731 *and* > 0.7185 (CoE-60), F-9 is refuted — CoE was the wrong trajectory summary, not the wrong idea.

3. **H-22 (Abstract-CoT shows compressed/qualitatively different breathing) is currently a vague qualitative claim.** Zigzag PH gives a principled, parametrization-invariant comparison: two trajectories have "the same dynamic topology" iff their zigzag barcodes match. **Mechanism**: if the zigzag barcode of Abstract-CoT trajectories (from 2604.22709) is a *strict subsequence* of natural-language CoT (consistent with "compressed"), H-22 is sharpened. If the barcodes are unrelated (different intervals, different counts), H-22's "compressed" framing is wrong — Abstract-CoT does qualitatively different topology, not compressed topology. If they match, H-22 is refuted — Abstract-CoT shows the *same* breathing topologically, just in fewer tokens. **Falsifiable experiment**: when H-22 runs, compute zigzag PH on both arms and report bottleneck distance.

## Methodologies extracted

- **0-dim zigzag persistence on graphs in O(m log²n + m log m)** — given a sequence of edge insertions/deletions on a graph, computes connected-component birth/death barcode in near-linear time. Uses Holm-Lichtenberg-Thorup dynamic connectivity data structure and a Morse-pairing technique.
  *Replication cost*: 1h CPU once filtration is built (fzz C++ binary, PHAT/Boost deps).
  *We'd plausibly run this*: **yes** — it's the cleanest test of "does dynamic topology beat static topology on residual streams?" which directly probes F-10's scope.

- **1-dim zigzag persistence on graphs in O(m log⁴n)** — pairs negative edges with the earliest positive edges that maintain 1-cycles across intermediate graphs.
  *Replication cost*: same fzz binary, slightly more setup to build the right graph filtration.
  *We'd plausibly run this*: **yes** — 1-dim is what would refute F-9 if trajectory cycles carry signal.

- **Alexander-duality extension to (p-1)-dim PH for ℝ^p-embedded complexes** — leverages the graph algorithms above for low-codim PH in higher ambient dimension.
  *Replication cost*: theoretical extension; needs custom code, not in fzz directly.
  *We'd plausibly run this*: **no** — residual streams aren't ℝ^p-embedded simplicial complexes; the embedding assumption doesn't fit our setting.

- **Filtration construction via dynamic k-NN graph over a token trajectory** — not in the paper itself, but the natural way to apply fzz to our setting: at each decoding step build a k-NN graph over recently-seen hidden states (or sliding-window vertex set), record edge insertions/deletions as the window advances.
  *Replication cost*: 1d CPU — needs a builder script that converts NPZ residual streams into the fzz `i v1 v2 ... / d v1 v2 ...` text format.
  *We'd plausibly run this*: **yes** — prerequisite for any of the above.

## Approaches & framings

- **Time-varying topology as the right primitive for sequence models.** The paper isn't about LLMs but its conceptual move — "deletions matter, not just insertions" — directly targets a methodological gap in our P7/P8 work. We computed PH at fixed snapshots; zigzag PH is the principled algorithm when the underlying object is a sequence. This reframes "is residual-stream topology informative?" from a static question into a dynamic one, with a separate null distribution we haven't tested.

- **Graph-valued time series as the unit of analysis.** Most of our P10/P11 features are vector-valued time series (DoM projections, CoE magnitudes). The paper's primitive is a graph-valued time series — every step is a discrete combinatorial object. This could intersect H-13 (head-level circuit attribution): attention patterns *are* graphs, and zigzag PH over attention graphs across decoding steps is a clean way to measure circuit-level dynamics that's currently outside our toolkit.

## Implementation details worth capturing

- **Code**: https://github.com/taohou01/fzz (C++ with Python bindings, MIT license per repo).
- **Dependencies**: Boost, PHAT (headers must be added to CMakeLists.txt manually).
- **Filtration format**: text file, lines of form `i v1 v2 ...` (insert simplex with these vertices) or `d v1 v2 ...` (delete simplex). Vertices are integer indices, ordered.
- **Output**: barcode = (dim, birth_index, death_index) tuples.
- **Build**: `mkdir build && cd build && cmake .. && make`. Python: `pip install -e .` from repo root.
- **Gotcha**: paper's algorithms are graph-only (0-dim and 1-dim); higher-dim PH on simplicial complexes still pays the O(m^ω) general cost. For our use case the graph case is the right one.
- **Scaling**: m = filtration size (total insertions+deletions). For a 1024-token trajectory with k=5 NN graph and sliding window 50, filtration size is ~50k. fzz handles 10⁶ trivially.

## Replicable intermediates

- **0-dim zigzag PH on a single MATH-500 trajectory** (sanity check, ~2h CPU): pick one correct + one incorrect 1.5B trajectory from `pathway11_h100/` cached L19 NPZs, build sliding-window k=5 NN graph (window=50 tokens), emit fzz filtration file, run binary, plot 0-dim barcode. Goal: confirm barcodes are non-trivial (multiple intervals) and visually distinct between correct/incorrect on a *single* example before scaling up.
- **Static-vs-zigzag null comparison** (~4h CPU): on the same trajectories, run static VR-PH on the union of all hidden states (the F-10 setup) and zigzag PH on the temporal filtration. If static is at Gaussian null but zigzag isn't, F-10 reading narrows.
- **Build script reusability**: the NPZ → fzz-filtration converter is the only new code; it can be reused for H-13 (attention-graph zigzag) and H-22 (abstract-CoT zigzag) without modification.
